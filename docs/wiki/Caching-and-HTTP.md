# Caching and HTTP

API errors return JSON. Missing website pages return the illustrated HTML 404.

```json
{
  "error": {
    "code": "VERSE_NOT_FOUND",
    "message": "Requested verse number is unavailable.",
    "request_id": "…"
  }
}
```

| HTTP status | Meaning / next step |
| :--- | :--- |
| `200` | Successful request |
| `204` | Successful OPTIONS preflight; no body |
| `304` | Content unchanged; reuse your saved body |
| `400` | Invalid input; read `error.message` |
| `401` | Supply the configured `x-api-key` |
| `404` | Route, verse or required candidates unavailable |
| `405` | Use GET, HEAD or OPTIONS |
| `414` | Request URL exceeds 4,096 characters |
| `500` | Unexpected error; report the request ID |

Most public responses use short caching and an `ETag`. Send the saved value in `If-None-Match`; a 304 has no body to parse. Random, health, error and key-protected responses use `no-store`. HEAD returns headers without a body. `x-request-id` identifies a request.

## Cache behavior

| Response | Cache-Control |
| --- | --- |
| Normal public API / HTML / scripts / styles | public, max-age=300, must-revalidate |
| Public daily response | public, max-age=60, must-revalidate |
| Public illustrations | public, max-age=86400, must-revalidate |
| Random, health and error responses | no-store |
| Responses while API_KEY is set | no-store |

These are handler headers. A hosting platform may add its own headers and policies. The repository does not implement a separate persistent cache.

## Conditional GET

1. Save a successful response body and its ETag.
2. Send the ETag as If-None-Match on your next request to the same URL.
3. If status is 304, use your stored body instead of parsing a new one.
4. If status is 200, replace both your stored body and ETag.

The implementation accepts matching weak ETags and comma-separated candidates. No-store responses do not include an ETag generated by this handler.

## Useful headers

| Header | Purpose |
| --- | --- |
| x-api-version | API contract version |
| x-dataset-version | Content checksum version |
| x-request-id | Unique request identifier |
| content-type | How to parse the response |
| content-disposition | Export download filename |
| vary: Origin | Origin-sensitive response metadata |
| x-content-type-options: nosniff | Prevent content type guessing |
| referrer-policy: no-referrer | Suppress outgoing referrer information |

HEAD performs the route handling and returns headers without a body. OPTIONS is a preflight response, not an API payload. Requests are read-only; POST and other writes return 405.
